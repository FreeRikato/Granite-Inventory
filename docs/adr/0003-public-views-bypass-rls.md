# The two public views run as their owner, not the caller

`v_public_business` and `v_public_catalog` are the only database objects the `anon` role can read, and they are deliberately created without `security_invoker` so they read the underlying tables as `postgres` and bypass RLS. The Supabase advisor reports this as "Security Definer View". It is intentional: each view projects exactly the columns the Public Catalog page may show (business name, tagline, WhatsApp number; product, variant, size, available count) and returns no rows while the catalog is switched off. The alternative, RLS policies granting `anon` row access on batches, products and settings, would expose whole rows including prices and suppliers. The seam test `catalog.test.ts` asserts that anon reads nothing from any other table or view and that no private column is present, so any change to these views must keep that test green.
